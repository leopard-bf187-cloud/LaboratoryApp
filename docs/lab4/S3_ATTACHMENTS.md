# ЛР4 — вложения Mood Diary в Amazon S3

Файлы изображений и PDF сохраняются непосредственно в приватный бакет S3 под ключами \`uploads/<random>.<ext>\`. Локальная папка \`storage/uploads\` не требуется. В PostgreSQL таблица \`entry_attachments\` хранит только ссылку на запись, ключ S3, имя оригинального файла, MIME-тип и размер.

## Перед развёртыванием

1. EC2 \`app-server\` должен иметь роль \`timecapsule-dev-app-role\` с разрешениями \`s3:GetObject\`, \`s3:PutObject\`, \`s3:DeleteObject\` для \`uploads/*\`.
2. В \`/var/www/mood-diary/.env\` добавить \`S3_BUCKET=timecapsule-dev-uploads-leopard\` и \`AWS_REGION=eu-central-1\`. IAM access keys добавлять **не нужно**.
3. Изменение \`composer.json\` требует обновления \`composer.lock\`. В каталоге приложения выполнить \`composer update aws/aws-sdk-php\` на машине с доступом к Packagist, сохранить обновлённый \`composer.lock\` в репозиторий, затем на EC2 выполнить \`composer install --no-dev --optimize-autoloader\`.
4. На EC2 выполнить \`php migrate.php\`, затем перезапустить PHP-FPM, если он кеширует конфигурацию приложения.
5. Убедиться, что настройки PHP разрешают загрузку файлов до 10 МБ: \`upload_max_filesize\` и \`post_max_size\` должны быть достаточно велики.

## Проверка

- Создать запись с PNG, затем запись с PDF; проверить появление \`uploads/*\` в S3 и Content-Type.
- Открыть вложение из списка записей: приложение проверяет вход и владельца записи, затем отвечает \`302\` на подписанную S3-ссылку на 5 минут. PNG отображается inline, PDF скачивается под исходным именем.
- Проверить недоступность прямого Object URL, подменённой или истёкшей ссылки.
- Удалить вложение или запись; при включённом S3 versioning появится Delete Marker.
- Проверить доступ другого обычного пользователя: чужие вложения должны быть недоступны.
- Проверить отсутствие \`storage/uploads\` на EC2: приложение продолжает работать без локальных файлов.

Замечание: существующие версии Mood Diary не имели файловых вложений, поэтому переносить пользовательские файлы из локальной папки в задании №10 было нечего.
